# Coloyond on-chain portfolio rebalancing: agent sprint checklist

**Status:** execution checklist, not evidence that a vault or funded flow exists.  
**Companion architecture:** [on-chain portfolio rebalancing plan](onchain-portfolio-rebalancing-plan.md).  
**Schedule assumption:** Sprint 0 is one proof week; Sprints 1–6 are two-week planning blocks for the first curated vault **and the card product**. Sprints 7–9 are appended expansion blocks. The former 13-week estimate covered the protocol path before the unfinished card experience was restored to scope; staffing, evidence and audit gates determine actual duration.

## 1. Mission, source of truth, and scope

Deliver the old spec's complete **choose allocation → generate expression → save → share/import → remix** Android experience and one curated, two-asset **WSOL/USDC** Solana vault with proportional deposits and in-kind exits, on-chain target/conditional policy, permissionless bounded Dutch-auction rebalancing, vault-owned fill fees and bounded keeper bounties. The creative experience remains useful when finance is unavailable. Two independent keeper operators provide liveness; neither has custody or policy authority. Android is the explicit wallet-signing client. The browser may show independently sourced, labeled read-only facts. A keeper, SDK, RPC service, API or UI cannot make an invalid transition valid: the program enforces every financial condition.

**Precedence for this mission:** the reviewed [card specification](../superpowers/specs/2026-10-09-coloyond-strategy-cards-design.md) and its [implementation plan](../superpowers/plans/2026-10-09-coloyond-managed-strategies.md) govern card identity, expression, client privacy, truthful observations, import/share/remix and mobile recovery. The user's newer fully on-chain direction replaces only their hackathon restriction on building a vault/keeper and their Symmetry/Jupiter financial execution path. [The new on-chain plan](onchain-portfolio-rebalancing-plan.md) governs that replacement protocol after Sprint 0 publishes its versioned product/risk amendment. Do not erase the old spec or reinterpret its `cb2:` records. The cross-chain swap draft is a separate vision and does not override either reviewed contract.

### Global definition of done

- [ ] A user can identify the published vault, its precise network/program/share mint/config revision, verified asset mints, target and actual weights, oracle age, current phase, fees/reserve and exit terms before signing.
- [ ] A user can complete choose/draft → generate real validated scene and optional caption → save immutable expression → local PNG/record share → strict import → visual or weight remix. A draft and an unavailable vault still complete this creative loop without fabricated execution.
- [ ] Saved strategy, scene and expression have separate versioned identities; verified imports preserve historical configuration and parent expression, never infer ownership or trading authority, and keep unknown/legacy records view-only.
- [ ] The signed entry, price observation, eligible trigger, bounded start, one or more atomic partial fills, fee/bounty booking, finish/expiry and in-kind exit are independently reproducible from on-chain accounts/events and transaction signatures.
- [ ] Each deposit/share/redemption/fee transition conserves token claims after deterministic dust and recorded liabilities; pause and keeper failure do not remove the program-level in-kind exit path.
- [ ] Every price-gated transition checks the pinned, fully verified on-chain Pyth feed, owner, feed ID, age, confidence and policy bounds. Stale/depegged/divergent data blocks **new risk**, never supplies a last-known executable price.
- [ ] Every fill respects inventory, size, auction curve, price/NAV-loss caps, fee/bounty bounds, no overshoot and **post-fee** drift improvement; failed solver routes leave the vault unchanged.
- [ ] User signing is explicit, intent is durably recorded before MWA handoff, confirmation is reconciled from chain state, and rejection/timeout/restart never becomes a false success or blind resend.
- [ ] Two replaceable keepers plus a third-party caller can perform eligible transitions; no private API, Hermes credential, indexer or single operator is an on-chain authority.
- [ ] Independent security review, verified deployed bytecode and actual `ProgramData` upgrade authority/control evidence pass before any public mainnet custody. Funded pilot amount/cap and rollout receive separate approval.

## 2. Agent operating protocol

Use the **legion** sequence: investigate evidence, freeze contracts, execute only truly independent packages in parallel, integrate branches serially, then validate the integrated result. Use the **ponytail** rule within each package: the smallest complete implementation that satisfies its acceptance criteria. Do not create speculative adapters, broad frameworks or UI/data scaffolds for later work.

1. **One integration owner per wave** records the exact `BASE_SHA`, the versioned contract/IDL it depends on, and the packages admitted. A later wave gets a new base from the merged integration branch; the current `99565d0a9dc11ec25d085e8ce93287c1a671e447` is historical context, not a perpetual base.
2. Parallel writers use **separate clones or independent sandboxes, never Git worktrees or the same checkout**. Each package has one branch such as `feature/rebalance-s2-oracle` or `fix/rebalance-oracle-age`. No `codex/` branch. Read-only reviewers may share a checkout.
3. A package can be in the same wave only when both its **write set is disjoint** and it has **no code/schema/runtime dependency on another active package**. Read dependencies are pinned to the wave base. New shared files, dependency catalogs, lockfiles, generated IDL, Android DI/app wiring, `src/ui/ColoyondApp.tsx` and `src/ui/app.css` each have one owner in a serial integration wave. If a dependency changes, stop the affected package and rebase/replan its contract before writing.
4. Each agent returns branch, commit, exact files, contract version, focused validation result, assumptions and unresolved risks. The integration owner reviews diffs, checks ownership, uses real `git merge --no-ff` commits (not cherry-picks), resolves conflicts centrally, runs the sprint validation matrix and records an evidence index. Agents do not merge each other's work.
5. For commits created for this user, verify `git var GIT_AUTHOR_IDENT` and `git var GIT_COMMITTER_IDENT` before committing; both must be `wlkit <114655923+wlkit@users.noreply.github.com>`. Before any authorized push, confirm branch name and author/committer of **every new commit**. GitHub login is push access, not commit attribution. Do not treat this checklist as authorization to push or release.
6. Never let an agent silently update a financial parameter, manifest, program ID, oracle account, fee cap or UI claim. Route such changes through the spec owner and a new revision. On gate failure, retain the last truthful read-only/current behavior and record a decision; do not expand unsafe bounds to make a demo pass.

**Package brief to copy:** `ID / sprint / wave / base SHA / branch / objective / read-only contract revision / exclusive write set / acceptance criteria / focused validation / excluded files / handoff evidence`. Assign a named human/agent owner and reviewer before starting. Keep sprint status and evidence links in this file through a **single integration owner**, never parallel edits.

## 13. Validation and evidence protocol for every package

- [ ] **Before code:** record contract/IDL revision, exact base SHA, exclusive files, dependency owners and deterministic acceptance vectors. Code against published mint/feed/program addresses, never token symbols or a UI fixture.
- [ ] **Package check:** run the smallest focused checks for touched behavior and retain command, output, commit SHA and network. A passing typecheck cannot substitute for program conservation evidence. Do not claim a Devnet market, keeper or audit from an SDK option or local test.
- [ ] **Merged wave check:** after `git merge --no-ff`, rerun affected checks against the merged SHA and inspect source/account/IDL compatibility. Re-run Kotlin/TS byte vectors whenever IDL or account layout changes. Review actual Git diff for overlap and reference-route drift.
- [ ] **Sprint check:** save a demo trace with before/after on-chain account balances and event sequence; list every rejected and stalled state, known limits and gate decision. An audit/review report needs its exact source/deployment commit and remediation status.
- [ ] **User-facing truth check:** target versus actual, NAV versus share market price versus executable quote, oracle timestamp versus UI retrieval time, submitted versus confirmed, and configuration revision are separate labeled facts. Unknown/stale/unavailable is an explicit state; no color alone conveys safety or profit.
- [ ] **Old product check:** cards and captions remain interpretation; exact mint/configuration, receipts and risks remain factual app text. Draft and imported cards are not executable authorities. Model output is validated data, not instructions; credentials, holdings and signatures are excluded from share payloads and model prompts.

Current local validation commands: `npm run typecheck`, `npm run build`; from `apps/android`, `./gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug --console=plain`; for the Anchor program, `cargo fmt --all -- --check`, `cargo check --locked`, `cargo test -p coloyond-vault --lib`, and `cargo-build-sbf --tools-version v1.57` (Solana CLI bin directory must be on `PATH`). Devnet, physical-wallet, external audit and verified deployment are distinct evidence categories; none is replaced by a local command.
