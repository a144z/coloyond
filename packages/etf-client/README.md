# ETF client boundary

This package contains provisional S5F fixture validators, a live Devnet candidate-account reader, an RPC transaction-receipt reconciler, and a wallet submission lifecycle. The fixture corpus remains component-level rather than a complete snapshot contract. The wallet lifecycle checks the pinned Devnet genesis and transaction fee payer before signing, journals the signed signature before sending, sends one raw transaction with RPC retries disabled, and then reconciles only through RPC. Submitted, processed, timed-out, and otherwise unresolved signatures remain `unknown`; an unknown signature is retained for later RPC-only reconciliation. Manual retry is exposed only after a fresh RPC-confirmed rejection plus complete unchanged token-balance metadata. Callers must reuse one stable `operationId` for a logical action and provide `retryOfSignature` only for the latest verified rejection. The lifecycle requires a durable journal implementation with atomic compare-and-swap semantics; this package intentionally provides no browser storage or UI. The receipt path does not yet read ETF pool state, share supply, or on-chain fee counters. Transaction builders and pool-state reconciliation depend on the frozen S5E IDL.

The fixture document remains explicitly `fixtureOnly`, and the ETF deployment manifest, program ID, production fee/risk limits, and S5E IDL are not frozen. Keep unsupported or unavailable observations tagged with their reason; a failed snapshot cannot include oracle, balance or pool value payloads, while a stale oracle-only observation can retain diagnostic metadata. Preserve `u64`/`i64` values as decimal strings. Validators reject decimal strings whose digit length already exceeds the declared wire range before constructing a `BigInt`; required text fields use the same explicit Unicode White_Space set as the Python fixture validator, and both validators require integer strings to end immediately after the last digit. `unknown` wallet actions never authorize automatic resend. Receiver `Full` verification and fixed Push Feed account status remain distinct.

Run `npm test --prefix packages/etf-client` and `npm run typecheck --prefix packages/etf-client`. Do not add schema-generation or RPC dependencies before the program interface is frozen.
