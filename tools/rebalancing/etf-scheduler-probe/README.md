# TukTuk Devnet account probe

Run `python3 tools/rebalancing/etf-scheduler-probe/probe.py` to read the current Devnet genesis, candidate TukTuk program account, config account and task queues. This standard-library probe is read-only. It decodes Anchor-discriminated config/queue accounts, queue bitmap occupancy, minimum crank reward and task-queue account lamports. It validates zero allocation padding, bitmap length and out-of-capacity task bits. For at most five active queues it inspects at most three occupied task IDs per queue using discriminator, queue and ID filters; the sample is therefore bounded to 15 task-account reads. The TaskV0 decoder recognizes `CompiledV0` versus `RemoteV0`, the `Now` and `Timestamp(i64)` triggers, compiled account/instruction indexes, signer-seed limits, description size and allocation padding. TukTuk has no interval, cron or account-condition trigger in `TriggerV0`; its tasks are one-shot unless the invoked program implements and funds a follow-up task protocol. The ETF `poke` path has no such protocol yet. Remote URLs and signer keys are intentionally not printed. Account lamports include rent-exempt allocation; the probe does not call that amount spendable funding. Existing unrelated task payloads do not prove ETF compatibility, task execution, or an available external crank-turner. The probe does not create a task queue or submit any transaction.

Run local decoder tests with `PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tools/rebalancing/etf-scheduler-probe -p 'test_*.py' -v`.

Queue registration and automated invocation require a separately reviewed wallet-signed Devnet flow. Do not interpret this program-account probe as proof that a queue is funded, a task is valid, or any third party will execute it.
